# Arel Focus

Arel Focus is a local-first macOS menu bar app that quietly tracks where your
attention goes — which apps you use and which Chrome tabs you have active —
and helps you review that time and assign it to your own projects.

- **No screenshots. No screen recording. No keylogging. No clipboard capture.**
  Arel Focus stores metadata only: app names, bundle IDs, window titles,
  domains, URLs, timestamps, and durations.
- **No cloud, no account, no telemetry.** Everything is stored locally in
  JSON under `~/Library/Application Support/Arel Focus/`. Nothing is
  uploaded anywhere by this app.
- **Optional website blocking.** A companion Chrome extension can enforce a
  blocklist during a focus session and redirect you to a local block page.

## Maturity

This is early software. There is **no signed release, no notarized binary,
and no Mac App Store listing** — you build it from source. Data is stored as
plain local JSON (v1); there is no migration tooling yet if the schema
changes. Treat this as a personal tool you run from source, not a polished
consumer app.

## Relationship to Arel OS

Arel Focus works standalone. It becomes more useful alongside
[Arel OS](https://github.com/vishmathpati/arel-os) through an optional,
one-directional file bridge:

- Arel OS (or any other controller) can drop command files into
  `~/Library/Application Support/Arel Focus/bridge/commands/` to start,
  update, cancel, or rescue a "Focus Hour" session.
- Arel Focus enforces the session locally (Chrome domain blocking) and
  writes its state and results back to
  `~/Library/Application Support/Arel Focus/bridge/state.json` and
  `bridge/results/<session_id>.json`.
- There is no network call in either direction — it's plain files on disk,
  polled every couple of seconds. If you don't use Arel OS, this folder
  simply stays empty and nothing reads or writes it.

Arel Focus does not require Arel OS to be installed, and does not hardcode
any Arel OS install path or port.

## Requirements

- macOS 14 (Sonoma) or later.
- Xcode command line tools with Swift 5.9+ (Swift 6 toolchains build it fine
  too — tested against Swift 6.3 on macOS 26).
- Google Chrome, only if you want tab tracking and website blocking. The Mac
  app's own app-usage tracking works without Chrome.

## Build and install from source

There is no installer. Clone the repo and build with Swift Package Manager:

```bash
git clone https://github.com/vishmathpati/arel-focus.git
cd arel-focus
swift build
```

That alone proves the app compiles. To actually run it as a menu bar app:

```bash
./script/build_and_run.sh run
```

This builds the app and native-messaging bridge, stages `Arel Focus.app`
into `./dist/`, and launches it with `open -n`. The app appears in the menu
bar and Dock. There is no `/Applications` install step in this script — if
you want it there, drag `dist/Arel Focus.app` over yourself, or run it
straight from `dist/`.

Other useful modes:

```bash
./script/build_and_run.sh --verify   # build, launch, confirm the process is running
./script/build_and_run.sh --logs     # stream the app's os_log output
```

### Enabling the Chrome extension (optional)

Tab tracking and website blocking need the unpacked Chrome extension plus a
native-messaging host. See `native-host/README.md` for the full walkthrough;
short version:

1. `./script/build_and_run.sh --verify` (builds the native bridge binary).
2. Open `chrome://extensions`, enable Developer Mode, "Load unpacked" on
   `chrome-extension/`, and copy the generated extension ID.
3. Set `AREL_FOCUS_EXTENSION_ID=<that id>` and run
   `./script/build_and_run.sh --install-bridge` to write Chrome's native
   messaging manifest (`native-host/com.arel.focus.bridge.json` is a
   reference copy only — the working manifest is generated by the script
   into Chrome's own `NativeMessagingHosts` directory, with the correct
   absolute path for your machine filled in automatically).
4. Reload the extension.

Without this step, Arel Focus still tracks native macOS app usage; you just
won't get Chrome tab/domain data or blocking.

## What's tracked, concretely

- Foreground app (name, bundle ID) and window title, sampled locally.
- Idle time via system idle detection.
- Chrome's active tab (URL, title, domain, favicon) and open-tab inventory,
  sent from the extension to the native bridge over stdio — never over the
  network.
- All of the above lands in local JSON/JSONL files under Application
  Support and is reviewable/exportable from the app's Settings and export
  views.
